SSH Security：Linux 遠端登入安全

認識 SSH 的基本原理、常見登入風險， 以及如何透過日誌分析與安全設定保護 Linux 伺服器。

01. 主題介紹

SSH（Secure Shell，安全殼層協定） 是一種透過加密連線遠端管理電腦的通訊協定。

系統管理員可以利用 SSH 遠端登入 Linux 伺服器、執行指令及管理系統。

因為 SSH 經常提供遠端管理入口， 所以帳號驗證與連線安全非常重要。

02. 基本原理

SSH 常見的登入驗證方式包括：

  • 密碼驗證（Password Authentication）： 使用帳號與密碼登入。
  • 公開金鑰驗證（Public Key Authentication）： 利用公私鑰進行身分驗證。

Linux 會記錄 SSH 的登入活動， 可協助管理員追蹤使用者與可疑來源。

SSH 日誌範例

Nov 08 10:00:01 server sshd[1001]: Failed password for root from 192.0.2.10 port 50001 ssh2
Nov 08 10:00:30 server sshd[1002]: Accepted publickey for alice from 198.51.100.20 port 50100 ssh2

上面是模擬測試日誌。 第一筆代表密碼登入失敗， 第二筆代表公開金鑰驗證成功。

03. 安全風險與常見問題

暴力破解（Brute-force Attack）

攻擊者可能短時間內反覆嘗試不同密碼， 企圖取得未授權的系統存取權。

弱密碼與帳號風險

使用容易猜測的密碼，可能提高帳號 遭到未授權存取的機率。

登入日誌判讀錯誤

單次登入失敗不一定代表攻擊。 需要結合來源 IP、時間、登入次數 與其他事件進行判斷。

04. 防護與改善方法

  • 優先使用 SSH 公開金鑰驗證。
  • 限制不必要的遠端管理帳號。
  • 使用防火牆限制 SSH 存取來源。
  • 定期檢查 SSH 登入日誌。
  • 使用 Fail2ban 等工具限制大量失敗登入。
  • 持續更新 OpenSSH 與系統安全修補程式。

常見 SSH 設定範例

PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no

以上為示範設定，並非所有環境都適合直接套用。 停用密碼驗證前，應先確認公開金鑰登入正常， 並保留可用的管理存取方式，避免無法登入伺服器。

05. 重點整理

  • SSH 是 Linux 常見的遠端管理方式。
  • 登入失敗次數與來源 IP 是重要分析資訊。
  • 短時間密集失敗登入可能代表密碼猜測行為。
  • 不能只憑單次失敗就認定系統遭到攻擊。
  • 公開金鑰驗證與存取限制可以降低風險。
